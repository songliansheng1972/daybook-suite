# daybook · 智能体编排中心「司南」

出：斯坦森（审方）｜ 2026-10-08 ｜ 落：`src/orchestrator.py`（单文件·零依赖）

> daybook 的两条产品线已立：**① 账本本体**（纯文本 append-only）、**② MCP 接口**（`daybook mcp`）。
> 本件是**第三条，也是把前两条焊成一个可跑闭环的那件**——智能体编排中心。
> 老宋批语：「另一个是智能体编排中心，咱们早就用上一半了，来个完整的？」

---

## 名号：司南

语出《韩非子·有度》：「先王立**司南**以端朝夕」——先王立司南，以定四方。

取义：**方向由器定，不因问者而异**。同一条，任何时刻、任何人来问，都得同一个下一手——
这正是本件与「让 LLM 去猜下一手」的分野。司南**不测天时、不观星象、不读正文**，
它只指一个恒定的方向。这也恰是 Cognition 那句「agent 贡献智能、不贡献动作」的器物化：
**编排器不贡献智能，只贡献方向。**

- 文件仍名 `orchestrator.py`（沿 daybook 的英文文件名惯例）
- 命令 `daybook 编排`，**别名 `daybook 司南`**
- 名号候老宋追认；名可更，性质不变

---

## 一、一句话

**不造调度器，只把 daybook 底座上已有的一切接上一个入口。**
编排中心不是一个新系统，而是**对同一批 append-only 卷的一层薄编排**——
不新存储、不新协议、不新依赖；真相仍在卷里，编排只是「谁该动、动到哪一步」的确定性查表。

---

## 二、六件原语 → 一个闭环

底座六件（W-DB-023-G3 已造，本件把它们焊起来）：

| 原语 | 模块 | 职责 | 本件如何用 |
|---|---|---|---|
| 身份 | `agent_registry.py` | HMAC-SHA256·不可伪造·可吊销 | `join` 发号・`who` 在场 |
| 任务 | `task_volume.py` | 待办→进行中→完成→待审→已审（终态拒迁） | `open/claim/submit/review` |
| 锁 | `agent_lock.py` | `fcntl.flock` + TTL 租约 | `claim` 用锁把「读-判-写」变原子 |
| 在场 | `agent_heartbeat.py` | 心跳卷，缺 ≥3 周期判 dead | `alarm` 找失联 |
| 消息 | `agent_message.py` | Unix socket + `[致=]` 寻址 | 与路由同址，可接推送 |
| 引用 | `cross_ref.py` | `[卷#L行-SHA8]` 防篡改 | 交活可带证据引用 |
| **路由** | **本件 `orchestrator.py`** | **类 → 角色 → 人（确定性查表）** | `pull` 定下一手 |

闭环（一步一条 daybook 卷记录，全程 append-only）：

```
join 入伙 ──▶ open 开单[工] ──▶ claim 认领(加锁·待办→进行中)
                                    │
                                    ▼
                         submit 交活[报·致=复审] (进行中→完成→待审)
                                    │
                                    ▼
                         pull 取件(查表算下一手=非作者) ──▶ review 裁决[审]
                                    │                          ├─ 通过 → 已审(终)
                                    └──────────────────────────┴─ 驳回 → 进行中(返工)
```

## 三、命令

```bash
python3 daybook.py 编排 join 汤姆           # 入伙（发 agent_id + secret）
python3 daybook.py 编排 who                 # 在场（注册×心跳）
python3 daybook.py 编排 open "实现 X" --by 汤姆
python3 daybook.py 编排 claim T001 ag-xxxx   # 认领（锁互斥·防并抢）
python3 daybook.py 编排 submit T001 ag-xxxx --to 皮特 --note "已交"
python3 daybook.py 编排 pull 皮特            # 取件（路由投影）
python3 daybook.py 编排 review T001 ag-yyyy 通过
python3 daybook.py 编排 board               # 看板（按状态）
python3 daybook.py 编排 alarm               # 体检（失联/孤儿/滞留）
python3 daybook.py 编排 selftest            # 端到端自检
```
`--root DIR` 指定卷根（默认本包自身）；`--rule/--roles` 换路由表/角色表。

两张表（纯文本·人可读可改，不藏在码里）：
- `orchestration_routing.conf`：`类[：关键词] = 角色`（如 `报=复审`、`报:驳回=返工`）
- `orchestration_roles.conf`：`角色 = 人/agent_id 列表`，含 `@非作者:施工`（实现「不自审」）

## 四、三条戒律（与路由层同）

1. **只读条头字段**（类/致/作者）与**关键词子串命中**——**绝不读正文语义做推理**。子串比对（`kw in hay`）是结构性校验，非语义理解；读语义即退化回 LLM 猜测，确定性回归。
2. **绝不写影子状态**——一切落到 append-only 卷。看板/收件箱皆**派生件，可删可重建**。
3. **表人可读可改**——路由表、角色表是纯文本，改规则 → 重跑 → 即重生。

> 要义：同一条，任何时刻算，都得同一个下一手。**定于查表，不定于推理。**

## 五、端到端验收（`编排 selftest` 全绿）

| # | 验项 | 结果 |
|---|---|---|
| 1 | 入伙 2 人 | PASS |
| 2 | 开单 → 待办 | PASS |
| 3 | 认领 → 进行中 | PASS |
| 4 | **重复认领被拒**（锁+状态校验） | PASS |
| 5 | 交活 → 待审 | PASS |
| 6 | 报条路由到**非作者**（剔汤姆 → 皮特/史泰龙） | PASS |
| 7 | 取件：皮特收到交活单 | PASS |
| 8 | 裁决通过 → 已审（终态） | PASS |
| 9 | 驳回 → 返工（进行中） | PASS |

真 CLI 串演亦跑通（入伙→开单→认领→交活→取件→裁决→看板→体检=干净）。

## 六、与另两条产品线的关系

| 产品线 | 入口 | 角色 |
|---|---|---|
| 账本本体 | `daybook index/watch/query` | 真相：纯文本 append-only |
| MCP | `daybook mcp` | 接口：把卷暴露给任意 MCP 客户端 |
| **编排中心** | **`daybook 编排`** | **协作：把卷变成多智能体的操作系统** |

三者同一二进制、同一底座（卷）、同一零依赖承诺。
**编排中心不新增任何存储**——它只是把「人肉开单、人肉传令」换成「确定性查表」，
把六件原语从一个抽屉里的零件，接成一台能自己转的机器。

---

## 七、已知边界

- 路由只对**已知类**确定性；未命中类的条落「广播」，不猜。
- `@非作者` 只在**两个以上**候选时可算唯一/多手；一名候选时退「待定」，不猜。
- 锁 `flock` 是进程级互斥，跨主机并发须靠共享文件系统或上层协调（与 daybook「一人一账本」定位一致）。
- 与 `agent_message.py` 的 socket 推送是**可接**关系（本件未强绑，避免引服务）。
