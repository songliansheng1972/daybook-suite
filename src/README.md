# DAYBOOK · 起居注

**你的记忆不该是一个黑盒——它该是一叠你能翻的账。**

纯文本 · 零依赖 · append-only ·读取百万条不崩。白箱记忆体：**真相在卷里，索引只是目录**，随时可从原文重算。

起居注：永久记忆！替上下文！可共享！即时消息平台！

## 名字的由来 —— 起居注

起居注，是**逐日记录帝王言行的官修档册**。**其名起于汉代（公元一世纪），到唐代成为定制，此后断断续续一直写到 1910 年。**

- **「起」＝起行 ·「居」＝居处 ·「注」＝注记** —— 记录帝王日常言行的原始档案。
- **专职史官执笔** —— 唐制：**起居郎**（属门下省）记天子言动法度，**起居舍人**（属中书省）录天子制诰德音；朝会之时对立于殿，**当廷记录**。
- **记录范围** —— 朝会、诏令、出行、祭祀、赏罚、经筵、引见……凡帝王动静皆记。
- **体例** —— 编年：**「以事系日，以日系月，以月系时，以时系年」**（《旧唐书·职官志》）。

**四条铁律：**

1. **只增不改** —— 写定的记录不得删改（制度约定）。
2. **记录者独立** —— 唐代定制：**连皇帝本人也不得调阅**。※ **此系制度理想，并非历代皆然** —— 宋以后即有君主索阅之例，清代亦有干预。
3. **编年为序** —— 逐日逐条，不许重排。
4. **修史底本** —— 起居注 → 实录 → 正史，三级递进。

两千年实践验证的只有一句：**重要的记录，必须只增不改、独立于被记录者。** 我们没发明什么 —— 只是把这叠两千年的账，挂给了 AI。

## 特点

- **纯文本** —— `cat` 就能读，记事本打开即看；不是二进制，不是私有格式。人机均可读。
- **零依赖 · 跨平台（Windows 实机验证待补）** —— 只用 Python 3 标准库；不联网。macOS / Linux / *BSD / 树莓派 / 随身硬盘拷到即跑。
  Windows 写路径**已实现**：互斥用命名互斥量（`CreateMutexW`，进程崩溃自动放弃），归属判用
  `realpath`/`commonpath` + 拒绝 reparse point（`openat`/`flock` 在 Windows 不存在）。
  两个平台共用同一套语义契约（同根一把独占锁、写不出根、追加后复核 inode、替换＝同目录临时件＋原子换入），
  差异只在系统调用层。
  **口径（不许写成已支持）**：Windows 路径已在代码中实现、**实机验证待补（第 1–6 项）**。
  验证包见仓根 `win_kit/`（`win_check.py` + `README_WIN.md`，零依赖、一条命令、六项自证 PASS/FAIL）；
  在收到 Windows 实机输出之前，POSIX 侧判据 W2 显式打印「未在 Windows 验证」并计数，不静默当通过。
- **只增不改** —— 一条一记，append-only；写不坏历史。每条必带作者 ID·可审可验可追。
- **快（4.0.6 实测·含根锁）** —— 40 万条 / 卷 23.7 MB：单条追加（含账本根排他锁）0.07 ms ≈ 1.42 万条/秒（14,236 条/秒）；追加一条后的增量 `index` 0.08 s；40 万条索引导一次 `query` 0.20 s；全量 `baseline` 5.96 s；持根锁 1.00 s 期间另一写者实测等待 1.01 s。复跑：`python3 bench/throughput_bench.py --check`（读数与判据同源，见 CHANGELOG）。旧口径「6.2–9.3 万条/秒」来自无锁追加，不代表本版全根串行写，已作废。
  **并发写者上限（实测·本机 macOS/APFS）**：8 / 64 / 256 / 1000 四点，写成功率全部 100%；单条追加 p50/p95/max 分别 0.06/1.27/1.46 ms、3.68/4.00/4.59 ms、15.67/16.28/18.22 ms、73.64/74.93/76.07 ms；等待 ≥250 ms 的写为 0 条（1000 档 20000/20000 成功）。复跑：`python3 bench/concurrency_bench.py --check`。
- **长跑不崩（判据：静态窗口稳态斜率；30 分钟，非 24 小时）** —— 写者停后留 3 分钟静态窗口，跳过停写后最后一次重建峰值，取窗口内 10 次采样的最小二乘斜率：**斜率 ≤ +24 MB/小时、fd 增长 ≤ 2** 才算不涨；绝对 RSS 只打印作参考（旧版 100 MB 绝对上限已不参与判定）。
  30 分钟实测：**12,507 条**、失败 0、坏行 0、条数一致、`watch` 56 轮无崩溃；静态窗口斜率 **-55.2 MB/h**、fd 19→19、RSS 6.5→3.2 MB。
  自证变红：`python3 bench/soak.py --leak-test` 用**同一套 judge** 跑合成泄漏（每 2 秒 +4 MB 不释放），必须判红（实测 +963.7 MB/h > 24）。合成泄漏抓不到，就不许写「soak 通过」。
  1 小时早期原始读数（旧判据）：14,250 条、0 失败、0 坏行、122 轮无崩溃、fd 19→19；首版阈值误判与修正经过见 CHANGELOG（旧记录未删）。
  复跑：`python3 bench/soak.py --minutes 30 --writers 8 --interval 1 --sample 15 --check --csv /tmp/soak.csv`
- **明文人可读 · 可查验** —— 账本是纯文本，**一行五段**（时间／类别／标题／作者／正文）。
  `python3 verify_plain.py 账卷.txt [索引 TSV]` 只用标准库（不导入任何 daybook 模块、不读 conf）
  即读出最后一条的时间/类别/标题/作者与完整性结论（坏行数、索引行数是否一致）和下一步动作；
  **裸终端版** `sh verify_plain.sh 账卷.txt [索引 TSV]` 只依赖 `sh` + `tail`/`grep`/`awk`/`od`，
  没有 Python 也能判读（判据 SH 会真跑，且 PATH 里没有 python）。
  **随目录迁移**：把仓内 `.py` 拷到新位置、换 `HOME`、`-I -S` 隔离模式下同样可判读（MIG 判据）。
- **多写者安全（Python 写者）** —— `O_APPEND` 原子追加；20 进程同写一卷零交错，1000 并发测试零失误。
  读侧完全通用，写侧边界见「定位与取舍」。
- **图是引用，不是嵌入** —— 图丢了，文本不烂。
- **可挂载为智能体的长期记忆** —— 能 `cat` 就能读，30 秒上岗。
- 跨年代，Python 3 + sh + C + Fortran + BASIC（1957–2026 跨年代），记忆永存！
- 可随项目移植，记忆零断档、推进零障碍。
- 跨平台、跨机多AI智能体共享永久记忆，macOS / Linux / 树莓派 / 旧笔记本 / 随身硬盘，AI Agent 直接读卷·不需要编排平台。
- 多AI智能体的即时消息平台。
- 用多卷+索引把"上下文限制"问题转化为"按需查询"问题。

## 定位与取舍

五条产品信条，按优先级当判据用（冲突时上面赢）：

1. **大厂做垄断、封闭、云端** —— 所以不接云、不做账号、不做平台绑定：凡「必须联网/登录某家服务才能用」的功能，不做。
2. **用户同时用两个以上 AI 平台** —— 所以数据层与平台无关：同一份账本，TRAE、DSH、终端、编辑器都可读写；凡依赖某家 API 或专有格式的方案，不做。
3. **单机、本地、人机可读** —— 所以默认零依赖、零服务、零配置：凡要装数据库/起守护进程/改环境变量的方案，不做。
4. **纯文本、明文、可查验、可追溯、多语言通用、裸终端通用** —— 所以账本是 UTF-8 文本、一条记录一行；`sh + tail/grep/awk/od` 即可读；凡加密/压缩/二进制索引，不做。
5. **不崩、不卡，1000 并发以下** —— 所以写路径全根串行、有公开实测上限；凡「先跑起来再说」的无锁旁路，不做。

**取舍示例（可判）**：要加一个配置项才能启用某能力 ⇒ 与③冲突；要加一个模式开关在两条写路径间切换 ⇒ 与④⑤冲突；要引入第二套锁或第二个写协议 ⇒ 与③⑤冲突。

**写入边界（如实写明）**：**任何语言、任何编辑器、裸终端都能读；写入只走 Python 客户端这一条路，不提供其它语言的写协议。** 非 Python 程序可以用子进程调用 `daybook_append.py` 写入；但不直接复制写协议——与 Python 写者并发安全必须共用同一把根锁（POSIX 是目录 fd 上的 `flock`，Windows 是命名互斥量），二者都没有可移植的 shell/Node 原生实现。别的语言自己拼写＝第二套实现，与极简原则冲突；所以不开放第二语言写协议。读侧不设边界：任何语言、任何终端都能读。

## 手工核验（裸终端，无 Python）

只装 POSIX shell 的机器（`sh` + `tail`/`grep`/`awk`/`od`），四条命令即可核验，不需要 daybook、不需要 Python：

```sh
# 1) 最后一条记录原文（时间 类别 标题 作者 正文 都在这一行）
tail -n 1 账卷.txt

# 2) 哪几行不是合法五段（无输出＝没有坏行）
awk '!/^\[[^]]*\] \[[^]]*\] \[[^]]*\] \[[^]]*\] /{print NR": "$0}' 账卷.txt

# 3) 末字节必须是换行（显示 \n 才完整；否则最后一条可能被截断）
tail -c 1 账卷.txt | od -An -c

# 4) 账卷可解析行数是否等于索引行数（两个数应相同）
grep -c '^\[' 账卷.txt; grep -c . 索引/index_账.tsv
```

也可一条命令跑完（`verify_plain.sh` 随包，纯 shell）：

```sh
sh verify_plain.sh 账卷.txt 索引/index_账.tsv
```

真实输出（判据 SH 同源）：

```
行数=2 可解析=2 坏行=0
最后一条：时间=2026-11-15 09:02:00 类别=审计 标题=第二条 作者=老宋
正文：乙
索引: .../index_账.tsv 行数=2 (账卷可解析 2) 一致
完整性：OK
下一步：无需动作（账卷与索引一致；需要新条目请运行 daybook_append.py）
```

坏行、二进制字节、末字节非换行、索引不一致，任一出现都会打印 `完整性：BAD（原因）` 并以非 0 退出。

## 应用场景

### 场景 1·AI Agent 协作开发

多个 AI Agent（如汤姆[审]方/史泰龙）共用一份起居注·按卷分工（协作卷/项目卷/语汇卷）·append-only 不互相覆盖·每条带作者可追溯。

### 场景 2·开发者长期记忆

开发者用 DAYBOOK 记录开发日志/调试过程/项目决策·不靠 AI 上下文窗口·按需查询·跨年代可读·零依赖可移植。

### 场景 3·团队协作工单流转

聊天室 + 多卷 + HOOK-A 自动追更·团队工单从聊天室触发关键词→自动追更到目标卷→归档可审计。

### 场景 4·跨年代数据存档

1957–2026 跨年代语言示例·证明 DAYBOOK 数据格式跨年代可读·不依赖特定软件版本·纯文本可永久保存。

### 场景 5·审计与合规

append-only 不可篡改·旧前缀哈希校验·任何篡改触发违例报告·满足审计留痕需求。

### 场景 6·知识工作者笔记

研究员/作家/学生用 DAYBOOK 记录研究/写作/学习卷·多卷分组织·按需索引·不丢失原文。

## 三行上手

```bash
cd daybook
python3 daybook.py index                 # 生成 / 刷新索引
python3 daybook.py query 类=报            # 按字段查询条目原文
python3 daybook.py watch 2               # 监视各卷，变动即重算
echo "要记的话" | python3 daybook_append.py 卷.txt 作者   # 追加一条
```

配 `daybook.conf`：一行一卷（`卷名 = 路径`）；改完重跑 `index` 即生效。

## 账之形（三条）

**一账＝一纯文本卷：行首时间戳起条、只许尾追、`cat` 可读。**  
三条之内不许动，三条之外随便；**索引不算账**。

## 多级目录（四库式）

平铺索引之上加一层**层级目录**，按需下钻取上下文（大账本不必拉全卷）：

```bash
python3 daybook.py multiindex              # 生成 multilevel/<卷>_catalog.md(.tsv) + catalog.md
python3 daybook.py multiindex --volume 协作     # 只出该卷目录（大账本省体积）
python3 daybook.py multiindex --order 子       # 总目录只出「按类」一序
```

**部(卷) → 类(二级) → 属(条目)**；总目录另按 **子(按类)／史(按年月)／集(按作者)** 三序跨卷汇总。
产出**全为派生件**（可删可重建），**索引是目录不是真相**——三条账形一字未动。
`watch` 模式卷变动后自动续建（`[multilevel] multilevel_enabled=是`）。零依赖·确定性（同索引源⇒同产出）。

**下游**：`daybook-mcp` 把目录挂成资源（`daybook://catalog/<卷>`）并按层级下钻（`daybook_multi_query`）；
`daybook-orch` 用它出变动摘要（`digest --push`）——**长上下文＝按需下钻**，**分发＝带层级的提要**。

## 边界（诚实）

- 纯文本＋低依赖 ⇒ 可检查、可携带；**不替代**权限、备份、恢复与合规方案。
- append-only 是**写入约定**，不是防篡改存储；身份与权限由上层（如司南）负责。
- 实测数据来自记录的测试环境，不同机器与负载结果会不同。

## 版本号与构建号（可复现）

> **升级须知（v4.0.6 行为变更，必读） / Upgrade notes (v4.0.6, read before upgrading)**
> 1. **非空卷首次索引退 5，需认基线**：首次索引不写回证据，先退 5；执行一次
>    `python3 daybook.py baseline`（`认基线`）后才写回游标与封存，之后 `index` 为 0。
>    证据缺失同样停在 5，直到认基线。
>    **The first index of a non-empty volume exits 5** and writes nothing back; run
>    `daybook.py baseline` once, then `index` is 0. Missing evidence stays at 5 until then.
> 2. **作者必填**：`daybook_append.py` 只接受 `卷 类 标题 作者 "正文"`；3/4 参旧形态、显式 `未标`/空值、`--name=` 一律拒写并退 2；独立模式也拒机器 id。
>    **The author is mandatory**: legacy 3/4-arg forms, `未标`/empty placeholders and `--name=` are refused with exit 2; standalone mode also refuses machine ids.

- **版本号**：标准**语义版本**，三包统一（同源同发）：**v4.0.6**。
- **构建号**：本包「产品 .py 件」行数之和（构建指纹·**非版本号**）；辅助件（`.sh` / `.c` / `.bas` / `.f` 语言端口、哨兵）与文档**不计入**。
