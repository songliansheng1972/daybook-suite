# DAYBOOK · 各语言实现范围说明

5 种语言实现是**金字塔结构**，不是平行结构。Python 是权威版，其他是功能子集保单。

## 设计哲学

"66 年保单"——**不是要求 5 种实现功能完全一致**，而是证明范式跨年代可移植。

- 栈会过期（Python 哪天没了）
- 范式永续（append-only + 索引可重算）
- 5 种实现各自证明：在自己的年代/栈/环境下，范式可跑

强行让 Fortran IV 输出 7 字段 tsv 不现实——1970s 大型机没有 utf-8/正则/复杂字符串处理。**功能子集本身就是证据**：范式在不同年代的栈里能跑多少跑多少。

| 5 字段 tsv 输出（卷/行号/时间/类/标题） | ✓ | ✓ | ✓ | ✗ | ✗ |

| 跨平台（macOS/Linux/Windows） | ✓ | ✓ | ✓ | ✗ | ✗ |
| 1970s 家用机可跑 | ✗ | ✗ | ✓ | ✓ | ✓ |

## 各语言定位

### daybook.py · Python 3 · 权威版（2000s-今）
- **范围**：全功能（7 字段 tsv + 编码检测 + watch + 跨平台）
- **角色**：开发/生产环境的权威实现
- **依赖**：仅 Python 标准库

### daybook.sh · POSIX sh + awk · 服务器子集（1970s-今）
- **范围**：5 字段 tsv 子集 + 卷首清单
- **角色**：无 Python 环境/服务器/嵌入式环境
- **依赖**：sh + awk（Unix 自带）

### daybook.c · ANSI C (C89+) · 编译型子集（1990s-今）
- **范围**：5 字段 tsv 子集（卷/行号/时间/类/标题）
- **角色**：从工作站到今天的最小可编译实现
- **依赖**：cc 编译器
- **注**：v1.1 起 K&R 风格签名改 ANSI，因为 C23 已正式移除 K&R 函数定义；保 1990s-今兼容即可（K&R 是 1970s-1980s 的产物，C 标准从 C89 起就推荐 ANSI 签名）

### daybook.f · Fortran IV · 大型机子集（1960s-今）
- **范围**：仅条目数（最小可跑子集）
- **角色**：超算/大型机环境的存活证明
- **依赖**：gfortran 或同等编译器

### daybook.bas · BASIC · 家用机子集（1970s-90s）
- **范围**：仅条目数（最小可跑子集）
- **角色**：Apple II/C64/BBC Master 等复古机环境的存活证明
- **依赖**：bwbasic 或同等 BASIC 解释器

## 跨语言一致性原则

1. **条目数对齐**：5 种实现跑同一卷，条目数必须一致
2. **tsv 字段对齐**：能输出 tsv 的（py/sh/c），前 5 字段（卷/行号/时间/类/标题）必须一致
3. **卷名对齐**：py/sh 读 conf 用配置键作卷名（协作/辞海/大宗师）；c 不读 conf，按文件名去 `.txt` 派生（协作卷/辞海卷/大宗师卷）——这是子集哲学允许的差异，不是 bug
4. **不可对齐项**：编码检测/watch/7 字段——这些是 Python 权威版独有

## 测试

`test/run.sh` 跑全部 5 种实现，v1.1 起加双跑对照验收：
- Python 必须跑通且条数 5/5/5（样本卷）—— 权威版验收
- 编码检测 3 卷全 utf-8 —— 权威版验收
- sh 必须跑通三卷各 5 条 —— 子集验收（与 py 前 5 字段对齐）
- C 必须编译并跑通三卷（表头+15 行=16 行）—— 子集验收（与 py 前 5 字段对齐）
- Fortran/BASIC 允许失败（编译器/解释器不可用），失败时打印但不退出
- 退出码 0 = 4 项全 PASS

本机无 gfortran/bwbasic 时：`PASS: 4 / FAIL: 0`。

## 红线

- **不强行对齐**：不让 Fortran IV 输出 7 字段 tsv——这违反"在自己年代能跑多少跑多少"的哲学
- **不替换权威版**：sh/C/F/BAS 不能替代 Python 作为生产实现
- **不删除子集实现**：每个实现都是范式跨年代可移植的证据
