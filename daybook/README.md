# DAYBOOK · 起居注

**你的记忆不该是一个黑盒——它该是一叠你能翻的账。**

纯文本 · 零依赖 · append-only ·读取百万条不崩。白箱记忆体：**真相在卷里，索引只是目录**，随时可从原文重算。

起居注：永久记忆！替上下文！可共享！即时消息平台！

## 名字的由来 —— 起居注

起居注，是**逐日记录帝王言行的官修档册**。**其名起于汉代（公元一世纪），到唐代成为定制，此后断断续续一直写到 1910 年。**

- **「起」＝起行 ·「居」＝居处 ·「注」＝注记** —— 记录帝王日常言行的原始档案。
- **专职史官执笔** —— 唐制：**起居郎**（属门下省）记天子言动法度，**起居舍人**（属中书省）录天子制诰德音；朝会之时对立于殿，**当廷记录**。
- **记录范围** —— 朝会、诏令、出行、祭祀、赏罚、经筵、引见……凡帝王动静皆记。
- **体例** —— 编年：**「以事系日，以日系月，以月系时，以时系年」**（《旧唐书·职官志》）。

**四条铁律：**

1. **只增不改** —— 写定的记录不得删改（制度约定）。
2. **记录者独立** —— 唐代定制：**连皇帝本人也不得调阅**。※ **此系制度理想，并非历代皆然** —— 宋以后即有君主索阅之例，清代亦有干预。
3. **编年为序** —— 逐日逐条，不许重排。
4. **修史底本** —— 起居注 → 实录 → 正史，三级递进。

两千年实践验证的只有一句：**重要的记录，必须只增不改、独立于被记录者。** 我们没发明什么 —— 只是把这叠两千年的账，挂给了 AI。

## 特点

- **纯文本** —— `cat` 就能读，记事本打开即看；不是二进制，不是私有格式。人机均可读。
- **零依赖** —— 只用 Python 3 标准库；不联网。拷到任何机器即跑（Windows / macOS / Linux / 树莓派 / 随身硬盘）。
- **只增不改** —— 一条一记，append-only；写不坏历史。每条必带作者 ID·可审可验可追。
- **快** —— 36.5 万条全量索引约 3.7 秒；100 万条追一条 0.28 秒，且不随总量增长。
- **多写者安全** —— `O_APPEND` 原子追加；20 进程同写一卷零交错，1000并发测试零失误。
- **图是引用，不是嵌入** —— 图丢了，文本不烂。
- **可挂载为智能体的长期记忆** —— 能 `cat` 就能读，30 秒上岗。
- 跨年代，Python 3 + sh + C + Fortran + BASIC（1957–2026 跨年代），记忆永存！
- 可随项目移植，记忆零断档、推进零障碍。
- 跨平台、跨机多AI智能体共享永久记忆，Windows / macOS / Linux / 树莓派 / 旧笔记本 / 随身硬盘，AI Agent 直接读卷·不需要编排平台。
- 多AI智能体的即时消息平台。
- 用多卷+索引把"上下文限制"问题转化为"按需查询"问题。
- 本地存储，自动备份，

## 应用场景

### 场景 1·AI Agent 协作开发

多个 AI Agent（如汤姆[审]方/史泰龙）共用一份起居注·按卷分工（协作卷/项目卷/语汇卷）·append-only 不互相覆盖·每条带作者可追溯。

### 场景 2·开发者长期记忆

开发者用 DAYBOOK 记录开发日志/调试过程/项目决策·不靠 AI 上下文窗口·按需查询·跨年代可读·零依赖可移植。

### 场景 3·团队协作工单流转

聊天室 + 多卷 + HOOK-A 自动追更·团队工单从聊天室触发关键词→自动追更到目标卷→归档可审计。

### 场景 4·跨年代数据存档

1957–2026 跨年代语言示例·证明 DAYBOOK 数据格式跨年代可读·不依赖特定软件版本·纯文本可永久保存。

### 场景 5·审计与合规

append-only 不可篡改·旧前缀哈希校验·任何篡改触发违例报告·满足审计留痕需求。

### 场景 6·知识工作者笔记

研究员/作家/学生用 DAYBOOK 记录研究/写作/学习卷·多卷分组织·按需索引·不丢失原文。

## 三行上手

```bash
cd daybook
python3 daybook.py index                 # 生成 / 刷新索引
python3 daybook.py query 类=报            # 按字段查询条目原文
python3 daybook.py watch 2               # 监视各卷，变动即重算
echo "要记的话" | python3 daybook_append.py 卷.txt 作者   # 追加一条
```

配 `daybook.conf`：一行一卷（`卷名 = 路径`）；改完重跑 `index` 即生效。

## 账之形（三条）

**一账＝一纯文本卷：行首时间戳起条、只许尾追、`cat` 可读。**  
三条之内不许动，三条之外随便；**索引不算账**。

## 边界（诚实）

- 纯文本＋低依赖 ⇒ 可检查、可携带；**不替代**权限、备份、恢复与合规方案。
- append-only 是**写入约定**，不是防篡改存储；身份与权限由上层（如司南）负责。
- 实测数据来自记录的测试环境，不同机器与负载结果会不同。
